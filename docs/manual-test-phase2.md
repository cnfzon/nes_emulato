# Phase 2 手動測試清單（需要 GUI，交給人確認）

自動化測試（`cargo test`、blargg、黃金畫面）驗證了 PPU 的暫存器行為、時序、渲染
與 save state，但**沒有**驗證過「真的遊戲在 GUI 上玩起來對不對」，也沒有驗證過
Debugger 面板與中文字型的實際顯示。以下請用自己合法取得的 ROM 手動確認。

## 準備

```bash
cargo build --release -p nes-app      # 交付/量測一律用這條（見 README）
cargo run -p nes-test -- info <rom.nes>   # 先確認 "Mapper: 0"
target\release\nes-app.exe
```

`File → Open ROM...` 載入。按鍵：方向鍵、Z = B、X = A、Enter = Start、
右 Shift = Select；F5 存檔、F9 讀檔。目前**沒有聲音**（APU 尚未實作）。

## A. Donkey Kong（NROM）

| # | 步驟 | 預期結果 |
|---|---|---|
| A1 | 載入後看標題畫面 | 標題 logo 與選單文字完整清楚、顏色正常（不是全黑／全白／雜訊／亂碼），沒有撕裂或每幀閃爍 |
| A2 | 右 Shift 切換選項、Enter 開始 | 選項游標會移動；Enter 進入第一關 |
| A3 | 方向鍵移動、X 跳、上/下爬梯子 | Mario 依輸入移動；精靈（Mario、木桶、大猩猩）形狀完整、方向翻轉正確，沒有錯位或缺塊 |
| A4 | 跳過木桶、爬到頂 | 碰撞與得分正常；畫面沒有多餘的殘影 |
| A5 | 遊玩途中按 F5，再移動一陣子，按 F9 | 立刻回到按 F5 時的位置與木桶配置，遊戲可以繼續正常玩 |
| A6 | Emulation → Pause → Resume | 暫停時畫面凍結、繼續後接續運行 |

## B. Super Mario Bros.（NROM）——重點是 sprite 0 分割與水平捲動

| # | 步驟 | 預期結果 |
|---|---|---|
| B1 | 標題畫面 | logo、`1 PLAYER GAME`、`TOP-` 分數等文字完整；上方狀態列（MARIO／金幣／WORLD／TIME）在正確位置 |
| B2 | Enter 開始，進入 1-1 | 進入關卡；金幣圖示會閃 |
| B3 | 按住右鍵前進 | 背景（雲、山、地面、磚塊）**水平平滑捲動**，沒有抖動、撕裂或 tile 接縫錯位 |
| B4 | 同時觀察畫面最上方狀態列 | **狀態列固定不動**（不隨背景捲動）；捲動時狀態列上下沒有抖動、沒有跳一條線 |
| B5 | 走過一整個畫面寬以上（越過 nametable 邊界） | 捲動持續連續，沒有突然跳回或出現空白欄 |
| B6 | 撞 `?` 磚、吃蘑菇、踩 Goomba | 磚塊彈跳、蘑菇/Goomba 精靈顯示正確、優先順序正確（Mario 與磚塊/水管的前後關係不亂） |
| B7 | X 跳（按住/短按）、Z 加速 | 跳躍高度隨按鍵時間變化；物理手感正常 |
| B8 | 走到水管/城堡等接近畫面右緣的地方 | 畫面右緣的精靈沒有被切掉或多出一條線 |
| B9 | F5 存檔、走一段、F9 讀檔 | 回到存檔時的位置**與捲動位置**，狀態列仍然固定 |

> **若 B4 看到狀態列與遊戲畫面交界處有 1 條掃描線的錯位／閃爍：** 這正是
> `docs/architecture.md` §13.2 描述的「PPU 落後 CPU 存取最多數個 cycle」造成的 ±1 條線
> 不確定窗口，請回報你看到的情形（是穩定的一條線、還是隨捲動閃爍），這會決定 Phase 3
> 要不要採用 §13.3 的拆段 catch-up。

## C. Debugger 面板（View → Debugger）

| # | 步驟 | 預期結果 |
|---|---|---|
| C1 | 面板頂端 | 有「暫停/繼續、單步指令、單步一幀、N 條指令 Trace 到檔案」控制；分頁：CPU、PPU、調色盤、OAM、Pattern、Nametable |
| C2 | **中文字型**：分頁「調色盤」、按鈕「單步指令」、狀態列「尚未載入 ROM」 | 中文是正常字形，不是方框 |
| C3 | PPU 分頁（遊戲執行中） | 掃描線 / dot 持續變化；PPUCTRL、PPUMASK、PPUSTATUS 有欄位解碼；v / t 會隨捲動改變 |
| C4 | 暫停後按「單步指令」數次 | PC、cycle、掃描線/dot 立即更新；**主畫面隨掃描線逐步畫出**（畫面上半是新幀、下半是上一幀，這是預期的） |
| C5 | 暫停後按「單步一幀」 | 幀數 +1，主畫面前進一幀；狀態列的 Frame 與 Debugger 一致 |
| C6 | 調色盤分頁 | 8 組（BG0–3、SP0–3）各 4 色的色塊，滑鼠移上去顯示數值與 `#RRGGBB`；遊戲畫面的顏色與這裡一致 |
| C7 | OAM 分頁 | 64 列（Y、Tile、Attr、X）；SMB 的 sprite 0（第 0 列）在狀態列下緣附近 |
| C8 | Pattern 分頁，切換 BG0–BG3、SP0–SP3 | 兩張 128×128 的 tile 圖（遊戲的圖塊）；切換調色盤時顏色改變；離開此分頁後不再消耗額外 CPU（可用工作管理員粗略觀察） |
| C9 | Nametable 分頁 | 4 張 256×240 的背景圖（`$2000/$2400/$2800/$2C00`）；因為 mirroring，其中兩兩相同；SMB 捲動時可看到背景延伸到相鄰的 nametable |
| C10 | 關閉 Debugger | 主畫面幀率不變；重新開啟可繼續使用 |
